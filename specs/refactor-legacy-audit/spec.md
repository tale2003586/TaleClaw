# 生产代码重构遗留审计与修复 Spec

## 背景

TaleClaw 经历了会话身份、运行时边界和 PostgreSQL 持久化等重构。当前已经发现一类可复现的遗留缺陷：新代码完成字段切换后，数据库中的旧字段或约束没有被完整清理，造成新旧结构同时存在，并在正常请求期间触发写入失败。

仓库中还存在兼容别名、旧消息格式适配和历史命名。它们不都属于缺陷：有测试、外部协议或明确兼容说明支撑的行为需要继续保留；历史报告与评测基线也不属于本次生产修复范围。

## 目标

- 系统性审计全部生产 Python 代码及 PostgreSQL 运行时表结构，识别可证明由重构不完整造成的残留。
- 修复字段、约束、迁移、读写路径和运行时接口之间的不一致，避免旧部署升级后才暴露故障。
- 为每项修复增加能复现旧状态并验证升级结果的自动化测试。
- 保留有测试、协议或明确产品需求依据的兼容行为，避免把正常的回退策略和历史兼容误判为技术债。
- 不修改历史报告、历史设计记录、实验脚本中的评测基线及 benchmark fixtures。

## 功能需求

- F1：建立生产代码中的持久化结构、迁移逻辑、兼容入口和新旧命名清单，并将每个候选项归类为“真实遗留”“有依据的兼容”或“非生产历史内容”。
- F2：对所有 PostgreSQL store 的建表结构、已有表升级路径、查询字段和写入字段进行交叉核对，识别旧库升级与新库初始化行为不一致的问题。
- F3：真实遗留必须通过幂等迁移完成修复；迁移应先保全有效数据，再处理默认值与非空约束，最后移除会妨碍新写入的旧结构。
- F4：生产代码中的领域命名、序列化字段、工具权限、路由身份和持久化字段必须保持一致；仅名称相似但语义不同的 `mode` 字段不得机械重命名。
- F5：每个数据库迁移修复必须覆盖至少三个场景：全新数据库、仅有旧结构的数据库、已经完成迁移的数据库；重复启动不得破坏数据或再次失败。
- F6：每个非数据库遗留修复必须有调用方或行为测试，证明旧残留已移除且当前公开行为保持不变。
- F7：对当前运行的 PostgreSQL 实例执行只读结构盘点；仅对被测试覆盖且已验证数据保全条件的真实遗留执行迁移，并在迁移后复核行数、必填字段和表约束。
- F8：输出最终审计报告，列出已修复项、明确保留的兼容项、排除项、验证证据，以及仍需人工决策的风险项。

## 非功能需求

- N1（数据安全）：任何删除列、收紧约束或转换数据的操作，都必须先验证目标字段已完整承接有效数据；无法证明安全时只报告，不自动执行。
- N2（原子性）：涉及多步结构变更的数据迁移必须在单一事务内完成；失败后不得留下半迁移结构。
- N3（幂等性）：初始化和迁移逻辑可以在新库、旧库及已迁移库上重复执行，结果保持一致。
- N4（兼容性）：不得移除有自动化测试、外部协议、公开入口或明确注释依据的兼容行为，除非同时具备替代路径和本次范围内的升级方案。
- N5（最小改动）：修复应聚焦已证实的不一致，不进行与缺陷无关的大规模改名、格式化或架构重写。
- N6（可诊断性）：迁移失败应暴露具体 store、表、字段和所需配置，不得静默回退到不同的持久化机制。
- N7（性能）：正常启动不得引入逐行 Python 数据搬运或无界全表扫描；结构盘点和集合式 SQL 迁移应在数据库侧完成。
- N8（安全与隐私）：审计输出和测试日志不得暴露数据库密码、模型密钥、登录凭证或用户消息正文。
- N9（可复现性）：所有结论必须有静态扫描、数据库查询或自动化测试证据；仅凭命名相似不得判定为遗留。

## 不做的事

- 不重写历史架构报告、阶段记录、实验结论或已经归档的设计文档。
- 不修改 security RAG 的 legacy 评测集合、对照实验脚本、benchmark fixtures 或历史指标命名。
- 不把所有名为 `mode` 的字段统一替换为 `active_agent`；trace 模式、检索模式、工具模式和其他独立领域概念保持原语义。
- 不移除 Telegram、飞书、子代理消息或公开工具接口中仍被测试覆盖的旧格式适配。
- 不进行与已证实遗留无关的目录重组、公共 API 改版、依赖升级、性能优化或代码格式化。
- 不删除当前数据库中的业务行、用户、消息、记忆、网关状态或 trace 记录。
- 不自动修改模型供应商、API 密钥、登录账号、网络入口或部署凭证。
- 不承诺清理仓库外部的其他数据库实例；本次只审计当前连接的 PostgreSQL 实例及仓库定义的升级路径。

## 验收标准

- AC1（对应 F1）：审计报告包含生产代码候选项清单，每项均标明分类、证据、处理结论和涉及模块；不存在未归类的扫描命中项。
- AC2（对应 F2）：仓库中每个 PostgreSQL store 都有“新建结构—升级结构—读取字段—写入字段”的核对记录；发现的不一致均有修复或明确风险说明。
- AC3（对应 F3）：对每个真实数据库遗留构造旧结构与代表性数据后，初始化可自动完成迁移；迁移前后业务行数一致，承接字段不存在无效空值，妨碍新写入的旧结构已移除。
- AC4（对应 F4）：生产运行路径不再读取或写入已废弃的领域字段；保留的同名或相似字段均在报告中说明其独立语义或兼容依据。
- AC5（对应 F5）：数据库迁移测试分别在全新、旧版和已迁移结构上通过；连续初始化两次的表结构和业务数据一致。
- AC6（对应 F6）：每个非数据库修复都有自动化测试证明当前公开行为不变，并且静态扫描不再命中被移除的遗留入口。
- AC7（对应 F7）：当前 PostgreSQL 实例迁移前后均记录表结构摘要与各相关表行数；迁移完成后所有必填字段有效，应用 store 可成功初始化并完成一次隔离的读写验证。
- AC8（对应 F8）：最终报告列出已修复、保留、排除和待决四类结果，并附实际执行的测试命令、数据库检查结果及失败项（如有）。
- AC9（对应 N1–N9）：代码审查与测试未发现数据丢失、半迁移结构、非幂等启动、无依据兼容删除、凭证泄露或无关的大范围改动。
