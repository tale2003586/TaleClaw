# Web 会话自动标题 Spec

## 背景

当前 Web 会话把 `chat_id` 同时用于稳定身份和界面显示。新会话的标识通常缺少语义，用户难以从会话列表快速判断每个会话讨论的主题。会话标题需要与稳定身份解耦，不能因为显示名称变化而影响会话链接、锁、历史记录或持久化主键。

## 目标

- 第一组完整问答形成后，根据首个用户问题及对应助手回答生成主题标题。
- 标题最多 20 个 Unicode 字符。
- 标题只用于 Web 界面显示，不改变 Session ID。
- 标题生成不阻塞、不破坏正文流式输出。
- 已生成标题的会话不重复生成或自动覆盖。

## 功能需求

- F1：当会话尚无标题且至少存在一组完整的“用户问题 + 助手回答”时，触发一次标题生成。
- F2：标题生成只使用该会话最早的一组用户问题和对应助手回答，不使用其他会话、长期记忆或后续消息。
- F3：生成结果必须去除引号、换行和多余空白，并限制在最多 20 个 Unicode 字符。
- F4：标题生成失败、超时或返回空内容时，不影响首轮回答和流式输出；使用首个问题的精简文本作为兜底标题。
- F5：标题写入 Session 元数据并持久化；已有非空标题时不得自动覆盖或重复调用模型。
- F6：会话列表和聊天页标题优先显示标题；不存在标题时继续显示原来的 `chat_id`。
- F7：对升级前已有但尚无标题的会话，在下一次成功回答后，使用历史中最早的完整问答生成一次标题。
- F8：Web 流式完成事件和会话查询接口返回最新标题，使前端无需刷新页面即可更新名称。

## 非功能需求

- N1：标题生成只能在正文回答完成后执行，不得缓存、合并或延迟正文的流式增量。
- N2：标题模型调用设置独立、可配置的短超时，默认 8 秒；超时立即使用本地兜底标题。
- N3：每个会话最多成功生成一次自动标题；并发请求沿用现有 Session 锁，避免重复生成。
- N4：标题生成使用现有 summary 模型路由，不新增模型供应商、密钥或数据库表。
- N5：标题内容作为普通 Session 元数据保存，不写入长期记忆、向量索引或模型对话历史。
- N6：升级后旧 Session 数据仍可正常读取；缺少标题元数据不视为错误。
- N7：前端显示标题时保持文本转义，不允许标题注入 HTML。
- N8：新增单元、集成和流式端到端测试，并保证现有完整测试继续通过。

## 不做的事

- 不修改或重命名 Session ID、数据库主键、Web URL 参数和会话锁标识。
- 不为标题新增数据库表或向量索引。
- 不把标题写入长期记忆或用于后续对话 Context。
- 不批量扫描、回填所有历史会话；旧会话只在下一次成功回答后按需生成。
- 不提供手动编辑标题、重新生成标题或恢复默认标题的界面。
- 不根据后续消息持续调整标题。
- 不为 Telegram、飞书或 CLI 增加会话标题展示；本轮只处理 Web 会话。
- 不改变正文模型、Prompt、流式协议和现有模型路由策略。

## 验收标准

- AC1：新会话首轮回答的文本增量正常逐段到达；回答完成后，会话获得基于首组问答生成的非空标题。
- AC2：生成标题去除引号、换行和首尾空白，长度不超过 20 个 Unicode 字符。
- AC3：标题模型失败、超时或返回空白时，正文仍正常完成，并使用首个问题的精简文本作为标题。
- AC4：同一会话后续继续聊天时，既有标题保持不变，标题模型不再调用。
- AC5：旧会话没有标题时仍能正常加载；下一次成功回答后，根据历史中的首组完整问答生成标题。
- AC6：会话列表、当前聊天页和流式完成结果展示或返回同一个标题；缺少标题时显示 `chat_id`。
- AC7：标题只存在于 Session 元数据与 Web 输出，不进入消息记录、长期记忆或向量索引。
- AC8：包含中文、英文、emoji、换行、引号和超长内容的标题都能安全规范化并按字符截断。
- AC9：完整测试通过，现有 Responses API 流式输出及 Chat Completions 流式输出没有回归。

| F5 | AC4、AC7 |
| F6、F8 | AC6 |
