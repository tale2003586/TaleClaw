# Minecraft 资源任务 Agent Spec

## 背景

TaleClaw 当前能够理解自然语言、调用工具并管理长任务，但还不能进入 Minecraft 世界执行游戏行为。本功能需要新增一个 Minecraft Java 版服务器 Agent：用户从 TaleClaw 下达资源收集指令，独立机器人账号进入离线模式服务器，自主规划并完成任务。

第一版聚焦生存模式资源任务。典型指令为“挖 30 个钻石”，任务数量按开始后的净新增计算，机器人任务开始前背包中已有的同类物品不计入目标。服务器具体版本不固定，应在连接时自动协商受支持版本。

## 目标

- 用户可以用自然语言创建资源收集任务，并持续获得任务状态、阶段进度和最终结果。
- Agent 能把资源目标拆成可执行步骤，包括检查物资、准备工具、寻找资源、移动、采集、拾取和计数。
- 游戏动作由确定性执行层完成，语言模型负责目标理解、计划选择、异常判断和重新规划。
- 任务在掉线、死亡、背包满、工具不足、路径失败或资源暂不可见时能够安全停止、恢复或给出明确阻塞原因。
- 第一版能够端到端完成常见地表与地下资源任务，并以“新增获得数量”作为统一完成判据。

## 功能需求

- F1：用户可以用自然语言创建单一资源目标，至少包含资源名称和正整数数量；系统应把常见中文名称规范化为游戏内资源标识，并拒绝含糊、未知或非资源类目标。
- F2：系统可以配置服务器地址、端口和机器人用户名，以离线模式登录 Java 服务器；未指定游戏版本时自动协商，并向用户报告连接、出生、断线和重连状态。
- F3：Agent 可以读取完成任务所需的受限世界状态，包括当前位置、维度、生命、饥饿、背包、装备、附近方块、掉落物和当前动作；不得把完整世界数据无界发送给语言模型。
- F4：任务开始时记录目标资源的背包基线；完成条件是当前背包中的目标物品相对基线净增加达到目标数量。死亡丢失、丢弃或消耗的目标物品不计为已完成。
- F5：Agent 可以生成并执行资源准备链，包括获取基础材料、制作工作台、木镐/石镐/铁镐、制作火把和选择合适工具；只允许执行达到目标所必要的准备步骤。
- F6：确定性执行层至少提供观察、移动、寻找方块、采集方块、拾取掉落物、制作物品、装备工具、吃食物、等待、停止和返回安全位置等高层动作；语言模型不得直接控制每个游戏 tick 或任意协议包。
- F7：第一版至少支持原木、圆石、煤、铁原矿和钻石五类资源。采集钻石前必须持有有效的铁镐或更高级镐，并同时识别普通钻石矿与深层钻石矿。
- F8：资源暂不可见时，Agent 可以采用受限搜索策略扩大已加载区域或进行安全分支采矿；搜索必须受最大时间、最大距离、最大挖掘方块数和重规划次数约束。
- F9：Agent 应持续发布任务阶段、净新增数量、当前动作、重试次数和最近错误；用户可以查询状态、取消任务，且同一机器人同一时刻最多执行一个资源任务。
- F10：遇到路径失败、工具损坏、背包满、生命或饥饿过低、掉线、死亡或服务器拒绝动作时，Agent 必须停止当前动作并按策略恢复、重连、重新规划或将任务标记为阻塞；不得无限重试。
- F11：任务状态应持久化。进程重启或短暂掉线后，系统可以恢复未结束任务，重新观察世界并校验背包基线；无法安全恢复时应请求用户重新开始，而不是错误宣称完成。
- F12：任务成功时返回资源名称、目标数量、实际净新增、耗时、主要准备步骤和最终背包摘要；失败、取消或阻塞时返回已完成数量、停止原因和可采取的下一步。
- F13：Minecraft Agent 应复用 TaleClaw 现有的会话隔离、模型路由、工具注册与授权、任务状态、取消机制、运行追踪和插件生命周期；Minecraft 模块只补充领域状态、领域计划和游戏动作，不建立第二套通用 Agent Runtime。

## 非功能需求

- N1（安全）：默认禁止攻击玩家、偷取或破坏容器、倾倒岩浆、使用爆炸物、修改出生点、执行服务器命令及大范围破坏；危险动作不得由语言模型临时绕过。
- N2（生存保护）：动作执行前后必须检查生命、饥饿、氧气、坠落、熔岩、溺水和敌对生物风险；达到安全阈值时，保命策略优先于任务进度。
- N3（有界自治）：每个任务必须配置总超时、动作超时、搜索半径、挖掘预算、重试次数和语言模型调用预算；任一预算耗尽后进入阻塞或失败状态。
- N4（确定性）：可重复的游戏操作由确定性状态机和高层动作实现；语言模型只能在经过校验的动作集合中选择，不得生成并执行任意 JavaScript、Python、shell 或网络请求。
- N5（幂等性）：重复的状态消息、网络重试或进程恢复不得创建第二个并行任务，不得重复计算已经丢失的物品，也不得把同一动作成功记录两次。
- N6（可观测性）：每个任务和动作都具有稳定标识，记录计划版本、状态转换、持续时间、重试、错误分类和数量变化；日志不得包含模型密钥或其他服务凭证。
- N7（性能）：高频世界事件在执行层本地聚合，向 TaleClaw 和语言模型发布节流后的摘要；正常运行不得因逐 tick 模型调用阻塞游戏客户端。
- N8（兼容性）：服务器版本默认自动协商；连接到执行层不支持的版本时应在动作开始前明确失败，不得以未知协议继续操作。
- N9（隔离）：Minecraft Bridge 只监听本机或显式配置的受信网络，使用共享密钥认证并限制请求大小；游戏服务器地址和机器人身份通过环境配置注入。
- N10（可测试性）：任务规划、状态机、计数和恢复逻辑可在无真实服务器条件下通过模拟 Bridge 验证；真实服务器端到端测试必须使用专用测试世界和机器人账号。
- N11（可维护性）：Minecraft 集成作为独立应用/插件边界接入 TaleClaw，优先组合现有 Runtime 端口和服务，不复制对话循环、模型调用、工具执行、trace、session、task 或取消基础设施；Node.js 协议对象不得泄漏到通用 Runtime，也不得改变现有聊天和 Coding Agent 行为。
- N12（服务器合规）：部署者负责确认服务器允许机器人和自动化；Agent 应提供清晰的机器人身份，不实现绕过反作弊、封禁或访问控制的功能。

## 不做的事

- 第一版不支持基岩版、单人世界、客户端 Mod 或直接控制用户本人的游戏角色。
- 第一版不承诺执行任意开放式 Minecraft 指令，仅接受资源收集目标。
- 第一版不实现建筑蓝图、红石工程、农业自动化、村民交易、附魔优化、下界/末地探索或长期基地经营。
- 第一版不主动进行 PvP，不狩猎玩家，不从玩家或未明确授权的容器中取物。
- 第一版不以战斗刷怪作为资源获取策略；敌对生物处理只限于避让、脱离和保命。
- 第一版不实现绕过反作弊、验证码、白名单、封禁、登录验证或服务器权限。
- 第一版不支持 Microsoft 正版账号登录；只支持用户已确认的离线模式服务器。
- 第一版不要求语言模型掌握方块级寻路、碰撞、协议包或逐 tick 控制。
- 第一版不保证在任意种子、极端地形、资源耗尽、受保护区域或服务器自定义规则下完成目标；无法完成时必须给出可诊断原因。
- 第一版不修改 TaleClaw 通用 Runtime 的核心语义，也不复制现有 Runtime 已提供的 Agent 循环、模型路由、工具授权、会话、trace 和取消能力。

## 验收标准

- AC1（对应 F1）：输入“挖 30 个钻石”“收集 16 个铁”等指令时生成规范化资源任务；未知资源、零数量、负数、多个冲突目标和非资源任务被明确拒绝。
- AC2（对应 F2）：模拟 Bridge 能验证离线登录配置、版本自动协商和连接状态事件；不支持版本与认证失败在任何游戏动作开始前返回可诊断错误。
- AC3（对应 F3）：一次观察返回规划所需的有限状态摘要，包含位置、生存状态、背包、工具和局部资源，但不包含无界区块或逐 tick 原始事件。
- AC4（对应 F4）：任务开始时已有 5 个钻石、目标为新增 30 个时，背包达到 34 个仍未完成，达到 35 个才成功；中途丢失目标物品会降低净新增进度。
- AC5（对应 F5）：模拟从空背包执行钻石任务时，计划先获得木材与工作台，再升级到石镐和铁镐，最后才允许采集钻石；已有合格工具时跳过无关准备步骤。
- AC6（对应 F6）：语言模型和 Runtime 只能调用已注册的高层 Minecraft 工具；任意代码、原始协议包、逐 tick 控制和未登记动作无法通过参数校验或工具授权。
- AC7（对应 F7）：原木、圆石、煤、铁原矿和钻石均有资源定义与采集策略；木镐/石镐尝试采集钻石会被执行层拒绝，铁镐或更高级镐能识别并采集两类钻石矿。
- AC8（对应 F8）：无可见资源的模拟世界会触发有限搜索与重规划；达到时间、距离、挖掘或重试预算后任务进入阻塞状态，不再产生游戏动作。
- AC9（对应 F9）：任务执行期间可查询阶段和净新增数量；取消后当前寻路/挖掘动作终止；第二个并发资源任务被拒绝或排队，不会同时控制机器人。
- AC10（对应 F10）：路径失败、工具损坏、背包满、低生命、低饥饿、断线和死亡场景分别触发预期恢复或阻塞策略，且重试次数有上限。
- AC11（对应 F11）：运行中任务持久化后可由新进程恢复；恢复时先重新观察并校验机器人、世界和背包，状态不一致时不会直接沿用旧成功进度。
- AC12（对应 F12）：成功、失败、取消和阻塞四种终态均产生结构化报告，包含资源、目标、净新增、耗时、阶段摘要和终止原因。
- AC13（对应 F13）：架构测试证明 Minecraft 应用复用了现有 Runtime 的 AgentSpec、模型路由、ToolRegistry/Executor、session、trace、task/cancel 和插件入口；没有第二套通用 Agent 循环。
- AC14（对应 N1–N12）：安全策略测试证明攻击玩家、访问未授权容器、爆炸物、岩浆、服务器命令、越权网络请求和无限重试均被拒绝；日志与任务状态不包含凭证。
- AC15（模拟端到端）：在确定性的模拟世界中，从空背包接收“挖 30 个钻石”，完成必要准备、有限搜索、两类矿石采集和掉落计数，最终以净新增 30 个钻石成功。
- AC16（真实服务器可选验收）：提供专用离线测试服务器后，机器人可以自动协商版本、加入世界、完成一个地表资源任务并安全退出；地下钻石任务是否完成取决于测试世界资源与预算，但必须正确报告成功或阻塞。
