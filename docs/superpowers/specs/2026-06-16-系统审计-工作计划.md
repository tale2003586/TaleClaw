## P0：记忆检索修复

**目标**：让 `recall_memory` 真正做检索，启用候选记忆流水线。

**修改文件**：
- [ ] `memory/store.py`——`recall()`：用 `history_vector_index` 向量搜索替代全文 dump
- [ ] `memory/vector_runtime.py`——`HISTORY_VECTOR_ENABLED` 默认改为 `True`
- [ ] `runtime/context.py`——`_build_memory_block()`：用 `memory_store.recall(current_request)` 替代 `memory_store.read_all()`
- [ ] `memory/lifecycle.py`——`after_turn()`：将记忆文件内容变更也索引到向量存储（不仅是 session turn）

**验收标准**：
1. `memory_store.recall("pytest preferences")` 返回相关记忆片段，而非全文 dump
2. `HISTORY_VECTOR_ENABLED` 默认 `True`——候选记忆流水线默认启用
3. 上下文中记忆块受预算控制，不随记忆总量增长
4. 已有记忆测试通过

**验收标准**：
1. `python -c "import config"` 无副作用（无环境变量修改、无 API 调用）
2. `python -c "from runtime.bootstrap import build_runtime"` 执行全部初始化

4. 全部已有测试通过

## P2：会话写入优化

**目标**：消除全量删插，加上内存 eviction 和 WAL。

**修改文件**：
- [ ] `sessions/session_store.py`——`save_session()`：追踪 `last_saved_seq`，只 INSERT 新消息
- [ ] `sessions/session.py`——`SessionManager.get_or_create()`：加 LRU 驱逐（内存中最多 128 个 session）
- [ ] `runtime/db.py`——`connect()`：SQLite 连接加 `PRAGMA journal_mode=WAL`

**验收标准**：
1. 同一 session 第二次调用 `save_session()` 写入 0 条消息行（无新消息时）
2. Session 缓存不超过 128 条；最久空闲的 session 被驱逐
3. SQLite 连接使用 WAL 模式
4. 已有会话测试通过

## P3：工具安全加固

## P4：记忆质量提升

**目标**：Embedding 信号干净、语义去重、候选存储高性能。

**修改文件**：
- [ ] `memory/lifecycle.py`——`_render_messages_for_embedding()`：只提取文本字段，跳过 JSON 结构
- [ ] `memory/dedup.py`——新增 `is_semantic_duplicate()`：用 embedding 余弦相似度（阈值 0.92）
- [ ] `memory/candidates.py`——`CandidateMemoryStore`：从 JSON 文件迁移到 SQLite 表

**SQLite 表结构**：
```sql
CREATE TABLE memory_candidates (
    id TEXT PRIMARY KEY,
    content TEXT NOT NULL,
    type TEXT NOT NULL DEFAULT 'candidate',
    confidence REAL NOT NULL DEFAULT 0.5,
    evidence_count INTEGER NOT NULL DEFAULT 1,
    source_refs TEXT NOT NULL DEFAULT '[]',
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    last_triggered_at TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'candidate',
    metadata TEXT NOT NULL DEFAULT '{}'
);
```

**验收标准**：
1. 工具调用结果的 embedding 文本显示人类可读摘要，非原始 JSON
2. "使用 pytest 做测试" 和 "用 pytest 运行测试" 被识别为近似重复
3. `CandidateMemoryStore.upsert()` 执行单行 INSERT/UPDATE，非全文件读写
4. 首次运行时自动将已有 `PENDING.json` 迁移到 SQLite

## 回滚与风险

| 风险 | 缓解措施 |
|------|----------|
| 默认启用 `HISTORY_VECTOR_ENABLED` 时 Qdrant 未运行会出错 | 优雅降级：bootstrap 时 Qdrant 连接失败则禁用向量功能并 log 警告 |
| config.py 重构可能导致 import 断裂 | 开始前 `git grep "from config import"` 全量扫描；一次性更新全部 |
| 会话增量保存可能遗漏消息 | 每个 session 追踪 `last_saved_seq`；用 add→save→add→save 序列测试 |
| 候选存储 JSON→SQLite 迁移 | 首次读取时自动迁移：`PENDING.json` 存在且 SQLite 表为空时导入 |
| 符号链接检查修复可能阻断合法工作流 | 只检查 RESOLVED 之后的路径是否在工作区内，不禁止符号链接本身 |
