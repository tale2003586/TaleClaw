## 建议实施顺序

```
第一轮（Context + Config）：C1-C15 + P1-P2
  理由：上下文是最底层基础设施，影响所有其他改动的评估基线

第二轮（Agent + Session）：A1-A12 + S1-S4
  理由：Agent 协作依赖稳定的 Loop 结构；Session 写性能直接影响生产可用性

第三轮（Memory + RAG）：M1-M8 + R1-R6
  理由：记忆系统和 RAG 都依赖向量基础设施；在前两轮稳定后再做

第四轮（Tool + Routing + Web + 测试）：T1-T4 + RT1-RT2 + W1-W8
  理由：安全加固和测试补全放在最后，不影响核心功能迭代
```
