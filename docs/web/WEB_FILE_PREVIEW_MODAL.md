# taleclaw 文件预览弹窗改动记录

> 改动日期：2026-05-31  
> 目标：移除文件页固定预览区域，将文本文件预览改为按需打开的弹窗。  
> 结论：改动已完成，并通过桌面端、手机端和完整回归测试。

## 一、改动原因

此前文件页采用固定预览布局：

- 桌面端：文件列表右侧长期占用一列作为预览区。
- 手机端：预览区被压到文件列表下方。

这种方式会持续占用页面空间，即使用户只想浏览目录或执行下载、重命名、删除操作，预览区仍然存在。

现在改为按需弹窗：

- 文件列表占满文件页。
- 点击文件行或“预览”按钮时才打开预览弹窗。
- 桌面端和手机端使用同一套交互。

## 二、实现内容

### 1. 页面结构

文件预览区域已从 `.files-pane` 中移出，改为原生 `<dialog>`：

```html
<dialog id="filePreviewModal" class="file-preview-modal">
  <section class="file-preview-dialog">
    <header class="preview-modal-head">...</header>
    <aside id="filePreview" class="file-preview"></aside>
  </section>
</dialog>
```

选择原生 `<dialog>` 的原因：

- 浏览器提供模态层语义。
- 自带遮罩层能力。
- 键盘焦点和可访问性基础更稳。
- 不需要引入第三方前端组件。

### 2. 打开与关闭逻辑

新增：

```text
openFilePreviewModal()
closeFilePreviewModal()
```

支持以下关闭方式：

- 点击右上角关闭按钮。
- 点击弹窗外遮罩。
- 按 `Esc`。
- 切换目录。
- 文件重命名后关闭旧预览。
- 文件删除后关闭旧预览。
- 文件上传后关闭旧预览。

### 3. 不可预览文件

如果文件不支持文本预览：

- 仍然打开弹窗。
- 展示“这个文件不能直接预览，可以下载查看”。
- 弹窗内保留文件名和下载入口。

这样用户不需要关闭弹窗后再回列表寻找下载按钮。

### 4. 文件页布局

桌面端文件页从：

```text
文件列表 | 固定预览区
```

调整为：

```text
文件列表
```

手机端也不再为预览区预留第三行布局。

### 5. 弹窗样式

- 桌面端最大宽度：`920px`
- 桌面端高度：`min(78dvh, 760px)`
- 手机端宽度：`calc(100vw - 20px)`
- 手机端高度：`min(82dvh, 720px)`
- 使用暗色背景、边框、阴影和轻量遮罩模糊。
- 长文本在弹窗内部滚动，不影响文件列表布局。
