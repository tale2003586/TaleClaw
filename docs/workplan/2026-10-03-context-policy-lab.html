数据如何流动

不可变原始事件→策略选择 raw / abstract / drop→保护用户要求 + 当前 TaskState→预算守卫 / 原生精确计数→模型与工具

选择改变可见内容，不删除源事件。文件改变、要求修订、分支复制后，失效沿证据 → 发现 → 决策 → 行动 / 完成依据传播。模型的“确认假设”始终属于解释，不能冒充工具验证。

直接使用

HTTP：继续同一任务并切换策略

POST /api/chat 或 /api/chat/stream 的现有请求中加入：

{
  "message": "继续检查 parser 的边界条件",
  "coding_task": {
    "mode": "continue",
    "context_policy": {
      "name": "adaptive",
      "recent_groups": 2,
      "preview_chars": 320,
      "soft_ratio": 0.70,
      "target_ratio": 0.45
    }
  }
}

task_id 可明确指定同一用户、同一父会话的任务。省略时用父会话绑定的活动任务。auto 只根据该绑定选择 new/continue，不猜“继续”等关键词。显式 new 不继承旧任务约束；branch 复制任务状态与来源引用。工作目录是否隔离由 workspace_mode 决定：worktree 使用独立 Git 工作树，in_place 使用原目录。工作树与交付能力由同期并行编码改动提供，不能把任务状态分支与文件副本视为同一件事。

选择优先级：本次显式策略 → 当前任务已保存的策略覆盖 → 父会话默认。无效字段、比例或策略名在模型调用前拒绝。

Python

runner.run_coding_task(
    parent_session=parent,
    user_text="继续验证",
    agent_spec=CODING_AGENT_SPEC,
    task_mode="continue",
    context_policy="masking",
)

明确修订用户要求

"coding_task": {
  "mode": "continue",
  "requirements_revision": {
    "objective": "检查并修复 parser",
    "constraints": [{"id": "scope", "text": "仅修改 src/parser.py", "required": true}],
    "remove_constraint_ids": ["old_constraint_id"]
  }
}

只提交实际需要修改的字段。被撤销约束保留审计历史；完整原始用户要求也保留，并标出后续修订的覆盖范围。旧完成依据退休后仍允许用新证据重新完成任务。

每种策略做什么

策略行为用途与边界
current · 默认保留现有 TaskState + 事件快照压缩路径。兼容基线；没有未经实测切换默认行为。
raw从源消息恢复全部候选内容，不主动压缩。对照组；最终硬预算仍生效，不承诺无限上下文。
masking旧工具观察替换为短预览、完整内容哈希和 event:// 恢复引用，保留工具事务。低开销基线；遮蔽摘要不构成新证据。
adaptive按当前焦点、结构化假设、证据引用选择完整内容、预览或移出；重要原文可置换无关预览。确定性启发式，无额外规划 LLM 调用；每轮重新读取源窗口。移除旧工具结果时保留有界执行索引（工具、关键参数、状态、恢复引用），索引也占预算；放不下索引时保留短事务。索引不是任务验证，也不保证模型不会重复调查。
nativeResponses server/standalone compaction；保留整份 canonical items 与 opaque 内容；每次单独刷新 instructions。需要明确支持的 endpoint、SDK 与 input-token-count。未知兼容服务不假定支持。

真实用户要求、开放工具事务、最近事务、没有恢复引用的观察不会被策略悄悄移除。最终仍超过硬上限时明确停止。每轮选择理由、源摘要指纹、raw/abstract/drop 计数记录在 context_policy_audit；原始证据可通过 read_artifact 恢复。

模型主动压缩

原有 compact(focus=...) 已从“仅记录请求”接成真实队列。待本轮所有工具结果闭合后由下一次上下文构建处理；连续无新工作请求被限制。请求被接受或队列处理完成，不保证该次实际缩短窗口；应核对实际请求审计与最终验收。它不能改变用户要求或把模型总结变成可信事实。

原生选项

{"name":"native","native_mode":"server",
 "native_compact_threshold":12000,"native_fallback":"error"}

native_mode 可用 server / standalone；native_fallback 默认 error，也可明确选择一种本地策略。回退仅用于调用前的能力判定；远端 404、未支持参数或计数不可用会明确终止，不静默换模型重试。切模型、endpoint 或 workspace 会切断旧原生窗口身份。首次切到 native 的原始输入必须能装入服务端上下文；不跨模型搬运密文。

统一实验命令

.venv/bin/python -m evaluation.context_experiments \
  --runner scripted \
  --policy current --policy raw --policy masking \
  --policy adaptive --policy native \
  --repeat 1 --max-steps 20 \
  --eval-root .evals/context

真实模型选择 --runner real；用户批准后，已固定 openai_relay / gpt-5.6-sol 完成隔离短任务烟测及上述真实压力矩阵。--policy-config 接受 JSON 配置数组，可调窗口、预览和压缩比例。每个任务有模型调用、工具调用、已知 token、时间预算；模型内部重试、压缩及结论提取纳入根调用账本。时间上限是协作式检查，不宣称能立即取消已发出的远端请求。

每个实验产生 matrix.json、rows.csv、report.html、独立任务日志与源码/数据指纹。报告保留失败和遗漏任务分母，记录实际生效策略、回退、可观察模型身份、缓存用量与证据恢复代理指标。不完整用量记为未知；辅助调用身份未覆盖时不做同模型配对。

固定模型的压力对照入口

两道合成题分别检查“失败测试 → 修复 → 再验证”和“读取四阶段日志 → 压缩 → 原样恢复早期证据 → 写入答案”。每份日志必须分轮完整读取；改动范围和最终测试由模型之外的验收器检查。

# 离线检查夹具与接线，不调用 API
.venv/bin/python scripts/run_context_policy_trial.py \
  --runner scripted --eval-root .evals/context-pressure

# 使用本次已批准的 OpenAI 路由，重新运行会产生新的 API 用量
.venv/bin/python scripts/run_context_policy_trial.py \
  --runner real --profile openai_relay \
  --expected-host sub.umapis.com --expected-model gpt-5.6-sol \
  --env-file .env --eval-root .evals/context-pressure-openai

脚本固定路由且禁用回退，使用复制的合成夹具，禁止生产数据库连接；这属于进程与工作目录隔离，不是操作系统沙箱。每题最多 20 次模型尝试、40 次工具尝试、250,000 已知 tokens、360 秒和 18 个推理步骤。时间/token 上限可能被一个正在进行的响应越过。为制造压力，本地窗口设为 32,000 tokens，目标比例 0.20；该数值不代表服务商模型的物理窗口。

对抗审查修掉了什么

攻击 / 故障条件修正后的行为
分支第一次保存后、运行前崩溃首次事务提交前就使继承证据及完成断言失效；事件、快照和检查点原子保存。
模型伪造 host 验证来源或同 patch 改前提再直接完成来源、任务作用域、证据新鲜度、依赖图与最终状态联合校验；不允许空引用洗白。
修改文件后先有新读数、再处理旧状态按事件顺序完成主机证据落地，再传播失效，避免误把未来读数永久判过期。
旧完成依据过期后永远无法再完成旧 basis 归档并退休；新鲜证据与重验项能恢复合法完成状态。
压缩掉工具结果后仍声称全文可见按实际 canonical 可见输出登记；密文不能代替可读取的工具原文。
原始日志极大，但 native 窗口已经很小本地指令预算与服务端精确输入计数分离，不把输出额度错误夹到 1 token。
native 回退到 adaptive，或跨模型路由变化记录真实策略及模型；不能冒充 native 成功，不做不公平配对。
失败样本没返回、usage 缺失失败仍在分母；缺失 usage 与模型身份是未知，不记免费或“同模型”。
短用户要求紧邻巨大模型回复，整组一直无法压缩adaptive 仅拆分普通闭合 user/assistant 组，保护用户原文和工具事务，保留源位置与最近事务边界。
移除旧工具结果后，模型忘记已读文件并反复调查增加有界执行索引，保留真实 event:// 引用；真实实验仍单独核查重复读取，不以索引存在推断模型已遵从。
pytest 返回 1，编码循环在修复前退出仅对已结束、输出完整的单条 pytest 命令标记诊断失败并允许继续修复；超时、复合命令和未知子进程保持原有停止规则。
Responses 自动 strict 化可选工具参数未显式声明时发送 strict:false；保留显式 true/false，并验证参数类型。普通、流式、原生计数调用共用转换路径。
文件变更后无法重读、分支引用失联、新测试依赖旧版本清理过期读取签名、仅在当前分支解析来源别名、记录主机已观察文件的执行前后版本；不宣称覆盖未观察文件或任意 ABA 变更。
第二题被中断，第一题完成结果却未入账逐题原子保存账本；可捕获中断明确区分已完成、被中断和未开始。未知用量保留未知，SIGKILL 只能保证此前已写入的检查点。

本批已知用量合计 1,114,490 tokens，另有2次响应的用量未知。各策略整批总量包含不同完成程度，不能据此宣称更省钱。四种本地策略的恢复题均有完整用量和模型身份；与 current 的成本配对各仅1个，不足以推断普遍收益。两组并行运行，也不据此比较延迟优劣。

现在需要什么决策

默认保持 current。 masking 在这次两题对照中完整通过，可作为扩大评测的优先候选；adaptive 的原样恢复链路已跑通，但仍会重复调查，保留实验性。native 需在路由明确提供所需能力后才有可比较结果。恢复题已有一组同模型、同任务且用量完整的配对；样本仍不足以判断生产质量或成本优势，因此本轮不升级默认策略。

自适应选择是启发式实现，没有训练新的压缩模型。完整的 RLM 递归推理执行器、跨任务自动经验学习不在本轮实现中；现有冷证据检索是其可复用基础。它们应在这套评测上独立增加策略和基准，避免把未验证研究结果直接装进默认生产路径。
