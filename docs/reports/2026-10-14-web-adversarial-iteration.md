调研依据：[Open WebUI / LiteLLM / Letta / Mem0 官方资料与适配报告](2026-10-13-similar-projects-research.md)。部署和接口契约见 [Web 使用说明](../../web/README.md)。

## 已交付功能

| 功能 | 用户可见行为 | 实现边界 |
| --- | --- | --- |
| 连接测试与模型发现 | 管理员测试当前草稿，选择发现的模型名称 | 仅显式请求 `/models`，保存不自动探测；列表成功不代表真实生成已验证 |
| 配置与路由预览 | 显示实际首选、备用、默认继承与用途别名 | 与保存共用校验，复用真实 ModelPool；不写配置、不发网络请求 |
| 跨页记忆搜索 | 搜索全部授权记忆，按状态、类型筛选后分页 | 字面子串参数化 SQL；作用域总数和匹配数分别显示；防抖及响应身份隔离 |
| 人工记忆治理 | 确认 / 拒绝候选，撤销有效记忆，填写操作说明 | 仅个人和已验证绑定任务可写；共享作用域只读；行锁内授权、版本、状态和 outbox 同事务 |

代码入口为 `web/model_diagnostics.py`、`web/runtime_settings.py`、`web/memory_view.py`、`web/memory_management.py`，网页操作均已接入相应页面。

记忆治理复用既有领域状态机和 PostgreSQL 转移逻辑。网页另传浏览器看到的 `expected_version`；不直接调用会重新读取最新版本的旧命令入口，以免丢失并发冲突检查。动作保留内容与证据，不硬删除，索引状态明确为 queued；查询时仍由真相记录验证检索资格。

## 三轮独立对抗审查

1. 基线攻击复现旧密钥跨目标复用、仅本页搜索和缺少候选治理入口。密钥现在绑定名称、Provider 和完整规范化目标，目标改变必须重新输入。
2. 网络攻击覆盖重定向、云元数据与 IP 变体、DNS 固定、慢速响应、压缩 / 超限响应、陈旧 revision。复现深层 JSON 异常并修复；模型探测有整体 deadline、并发与响应边界。
3. 运行和治理攻击覆盖共享凭证异常回显、跨账号与共享作用域、陈旧版本、状态变化、事务回滚和索引队列。公共异常改为固定文案；额外投影模型失败公共事件，内部 Trace 的完整内容不会直接复制到该错误事件流。

独立测试保存在 `tests/test_web_adversarial_iteration.py`，62 个攻击场景全部通过。后续迭代可继续复用这些回归场景。

- 前端全量：96 passed。TypeScript、ESLint、生产构建及 `git diff --check` 通过。
- 隔离 PostgreSQL：验证权限与 CAS、并发冲突、证据保留、状态 / outbox 原子性、字面搜索与分页，不改写用户实际记忆。
- 真实本地 HTTPS：证书仅含原 DNS 名称，无 IP SAN；固定连接 127.0.0.1 后仍以原域名发送 SNI 并校验证书，Host 与 `/v1/models` 路径正确。
- 使用模拟数据检查桌面和移动布局、发现模型选择、路由预览及记忆操作确认界面。

本轮没有调用真实模型 API，也未执行生产记忆动作。已有部署加载本次新代码和构建资源后即可使用这些入口；模型配置之后的更改继续按新任务快照生效。
