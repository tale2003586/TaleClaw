# TaleClaw 控制台 Untitled 视觉与主题重构 Spec

## 背景

当前 TaleClaw React 控制台已经覆盖聊天、日志、Runs/Trace、设置、文件、分析、记忆和状态八个主视图，并具备桌面侧栏、移动抽屉和响应式布局。现有视觉以荧光黄绿色、较大的页面标题、较宽松的留白和较大圆角为主，与 `Untitled/` 中提供的目标界面存在明显差异。

`Untitled/` 参考图呈现的是面向 Agent 运维与开发工作的高密度控制台：使用固定侧栏、紧凑顶栏、青绿色强调色、低圆角、细描边、克制阴影、清晰的状态颜色，以及适合长日志和 Trace 浏览的信息层级。参考图只提供暗色方案，本次还需要建立与之对应的浅色方案。

## 目标

- 在保留现有功能和信息架构的前提下，使八个主视图形成与 `Untitled/` 参考图一致的工作台视觉语言。
- 将当前荧光黄绿色视觉替换为青绿色主强调色，并统一页面密度、层级、边框、圆角、控件和状态反馈。
- 提供完整的浅色与暗色主题：首次访问跟随操作系统，用户可手动切换，并持久记住选择。
- 保持桌面与移动端的可用性、键盘可访问性、减少动态效果支持和现有业务行为。

## 功能需求

- F1: 桌面应用外壳采用参考图中的固定左侧导航和右侧工作区结构，侧栏品牌、主导航、会话列表和账户区具有明确分区；现有折叠行为继续可用。
- F2: 聊天页采用紧凑顶栏、居中的消息阅读区域、区分用户与助手的消息层级，以及固定在工作区底部的输入区域；模式选择、技术输出和流式状态继续可用。
- F3: 日志页采用适合扫描的紧凑指标、筛选工具栏和结构化表格，信息、警告、错误状态具有可辨识且跨主题一致的语义颜色。
- F4: Runs/Trace 页采用参考图中的运行摘要、指标带和纵向步骤时间线，复杂 Payload、工具调用、模型事件和最终状态保持清晰可读。
- F5: 设置页及其余管理页采用参考图中的低圆角面板、紧凑表单、清晰分组和一致控件；重复内容可使用面板，但页面区段本身不额外套装饰性卡片。
- F6: 应用提供可发现的主题切换控件，使用太阳和月亮等熟悉图标表达浅色/暗色状态，并带有可访问名称和悬停提示。
- F7: 用户从未手动选择主题时，应用跟随操作系统浅色/暗色偏好；用户手动切换后，刷新和重新访问均恢复该选择。
- F8: 浅色与暗色主题覆盖应用外壳、文本、面板、输入控件、表格、代码块、弹窗、骨架、焦点、悬停、选中及成功/警告/错误状态，不出现只在单一主题下可读的残留固定颜色。
- F9: 页面在初始化时直接使用正确主题，避免先显示错误主题后跳变；主题变化不刷新页面、不重置当前视图或业务状态。
- F10: 390px 移动端继续使用抽屉导航，主题切换入口可操作，页面内容、表格、Trace、长路径和代码内容不会造成不可控的页面级横向滚动。

## 非功能需求

- N1: 继续使用现有 React、TypeScript 和 CSS 架构，不引入大型 UI 框架或主题运行时依赖。
- N2: 颜色通过语义化设计令牌管理，组件不依赖只适用于暗色背景的硬编码前景色或背景色。
- N3: 参考图作为视觉方向而非像素级复制；现有八视图、中文内容、真实数据形态和权限边界优先。
- N4: 主题控件、导航、表单、Disclosure 和 Modal 可使用键盘操作，并具有可见焦点；文字和关键控件满足清晰可辨的对比度。
- N5: 动效保持克制，并继续尊重 `prefers-reduced-motion`；主题切换不使用大面积或长时间动画。
- N6: 不改变现有 API 请求/响应、路由权限、会话、聊天流、文件操作、设置预览和 Runs 缓存行为。
- N7: 1440x900 与 390x844 两个目标视口下，布局稳定、文本不重叠、固定控件不遮挡主要内容。
- N8: 主题偏好只保存主题标识，不持久化敏感配置、消息、Trace Payload 或其他业务数据。

## 不做的事

- 不修改登录和注册页面的视觉或业务流程。
- 不实现第三套主题、用户自定义颜色、主题编辑器或服务端主题同步。
- 不按照参考图虚构不存在的 Live Tail、Re-run、设置保存或分页能力。
- 不改变后端接口、权限规则、Runtime、Trace 格式或数据存储。
- 不重构现有页面的数据获取和领域逻辑，除非视觉组件接入所必需。
- 不追求与参考图逐像素一致，也不照搬参考图中的英文示例数据。

## 验收标准

- AC1: 1440x900 暗色桌面截图中，固定侧栏、紧凑顶栏、青绿色强调色、低圆角面板、细描边和高密度信息结构与 `Untitled/` 的整体视觉语言一致。
- AC2: 聊天、日志、Runs/Trace 和设置四个重点页面分别体现对应参考图的布局与层级，其余四页使用同一套视觉规范。
- AC3: 首次访问分别模拟系统浅色和暗色偏好时，页面直接呈现对应主题；不存在可见的错误主题闪烁。
- AC4: 用户手动切换主题后无需刷新即可全局生效，刷新页面仍保留选择，当前 Hash 视图和页面状态不被重置。
- AC5: 浅色和暗色下，导航、面板、输入、表格、代码、Modal、状态色、焦点和交互状态均清晰可读；不存在明显的暗色硬编码残留。
- AC6: 主题切换控件具有图标、可访问名称、状态提示和键盘焦点，可在桌面侧栏与 390px 移动抽屉中正常操作。
- AC7: 1440x900 和 390x844 下八个视图无页面级横向溢出，长 Run ID、Payload、代码和路径在自己的容器内换行或滚动，内容及控件不重叠。
- AC8: 现有 TypeScript 检查、Lint、React 测试、生产构建和相关 Python 测试通过，主题逻辑具有针对系统默认、手动切换和持久恢复的自动化覆盖。
- AC9: 浏览器分别在浅色/暗色、桌面/移动组合下完成八视图冒烟，控制台无未处理异常，页面截图和像素检查确认内容非空且布局正确。
