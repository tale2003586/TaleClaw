# TaleClaw Web 控制台前端改版 Spec

## 背景

当前 Web 前端已提供聊天、会话、文件、分析、记忆、状态和 Workspace 选择能力，后端也已经提供管理员可用的 Run 列表与 Run Detail API，并以 `.runs/<run_id>/` 下的 `run_state.json`、`metrics.json` 和 `trace.jsonl` 作为执行事实来源。

`Untitled/` 中的设计图给出了新的深色控制台视觉方向，包括聊天、日志、设置和 Agent Run Trace 页面。设计图中的示例字段与当前 Runtime 的真实数据并不完全一致，因此本次改版以现有代码、接口、权限和 Runtime 工件为准，借鉴设计图的信息层级、色彩、导航和卡片布局，不复制不存在的业务能力。

## 目标

- 将现有 Web 页面统一为设计图所示的深色 Agent Runtime 控制台风格。
- 保持现有聊天、会话、文件、分析、记忆、状态、登录与 Workspace 行为可用。
- 新增日志页，用可检索、可筛选的方式查看现有 Run Trace 事件。
- 新增 Runs / Trace 页，用列表和详情视图复盘真实 Agent Run。
- 新增设置页的前端界面原型，展示模型、路由与 Runtime 策略配置分组，但本期不读写 `.env`。
- 在桌面和移动端都保持清晰、可导航且不发生主要内容溢出。

## 功能需求

- F1: 全局外壳采用固定主导航、统一页头、深色内容区和青绿色强调色，并提供聊天、日志、Runs、设置以及现有工具入口。
- F2: 聊天页沿用现有会话选择、新建/删除、流式输出、停止生成、模式切换、Markdown、工具活动和 Workspace 行为，同时按设计图调整信息层级与视觉布局。
- F3: 日志页从现有 Run/Trace 数据中展示时间、事件级别、来源和消息摘要；支持文本搜索、级别筛选、Run 选择、刷新及空态/错误态。事件级别由现有事件名和 payload 状态推导，不修改原始日志事实。
- F4: Runs 页展示现有 Run 列表及状态、模式、会话、开始时间、步骤、模型调用和工具调用；支持选择 Run、刷新、状态筛选和空态/错误态。
- F5: Trace 详情展示选中 Run 的真实 run state、metrics、用户请求摘要、步骤时间线、模型调用、工具调用、Subagent、错误/停止原因和最终结果；缺失字段以空态或“不适用”呈现，不伪造设计图数据。
- F6: 设置页提供模型 Provider、模型路由、上下文策略、记忆/RAG、反思与 Subagent 等分组化前端控件，并明确标记为“界面预览/尚未接入保存”；控件不得写入 `.env`、浏览器持久存储或运行时配置。
- F7: 文件页保留浏览、预览、上传、新建目录、重命名、删除和下载行为，并适配统一导航与页面布局。
- F8: 分析页保留文本提交、回复展示和记录下载行为，并适配统一导航与页面布局。
- F9: 记忆页继续展示当前后端返回的记忆文件与内容，并在统一页面中提供选择、刷新、空态和错误态。
- F10: 状态页集中展示当前用户、角色、会话、模式、Runtime 健康、应用根目录、Coding Workspace 和可获得的 Run 概览；不得把未知状态显示为正常。
- F11: 管理员专属的 Runs、Trace 和日志数据遵循现有后端权限；普通用户看不到无权访问的导航入口，也不能通过前端绕过 API 权限。
- F12: 页面刷新后恢复合法的当前主视图；若保存的视图因权限或版本变化不可用，则回退到聊天页。

## 非功能需求

- N1: 不引入新的前端框架或构建链，继续适配现有原生 HTML、CSS 和 JavaScript 结构。
- N2: 不改变现有 API 的请求/响应契约；现有接口是页面数据适配的最高优先级。
- N3: 日志和 Trace 页面必须对缺字段、未知事件类型、超长 payload、空列表和请求失败进行容错。
- N4: 用户可见文本默认使用中文；Run ID、事件名、模型名和工具名等技术标识保留原值。
- N5: 交互控件具备键盘可达性、可见焦点、语义标签和基础屏幕阅读器文本。
- N6: 桌面端主要适配 1280px 及以上宽度，移动端在 860px 及以下使用可关闭的抽屉导航；页面不得产生不可控的横向滚动。
- N7: API Key、密码、Token 等敏感内容不得由新增前端页面读取、缓存或显示。
- N8: 保留用户工作区中的既有未提交修改，不改动与本功能无关的 Runtime 业务逻辑。

## 不做的事

- 不新增、修改或热重载 `.env` 配置。
- 不实现设置页保存、配置校验、密钥查看、模型连通性测试或 Runtime 重启。
- 不新增独立系统日志采集器、日志数据库、WebSocket/SSE 日志尾随或跨进程事件广播。
- 不修改 Trace 工件格式、Runtime 执行流程、模型路由、记忆策略或工具策略。
- 不伪造设计图中的 Token、上下文压缩、模型调用或工具调用数据。
- 不重做登录/注册页面，也不新增权限角色。

## 验收标准

- AC1: 用户可通过统一主导航进入聊天、文件、分析、记忆、状态和设置页面；管理员还可进入日志与 Runs 页面。
- AC2: 现有聊天关键流程可完成，流式活动、停止按钮、模式切换和会话操作没有因改版失效。
- AC3: 管理员打开日志页可看到由真实 Trace 事件生成的日志行，并能按关键词、级别和 Run 筛选；无 Run 时看到明确空态。
- AC4: 管理员打开 Runs 页可看到真实 Run 列表，选择一项后可查看对应的真实 Trace 详情和指标。
- AC5: Trace 中未知或缺失的数据不会导致页面崩溃，长 payload 可折叠或滚动查看。
- AC6: 设置页展示约定的配置分组和控件，同时明确显示未接入保存，操作不会修改 `.env` 或浏览器持久配置。
- AC7: 文件、分析、记忆和状态的既有数据加载及主要操作在新布局中仍然可用。
- AC8: 普通用户界面不展示管理员日志/Runs 入口，直接请求管理员 API 时仍由现有后端拒绝。
- AC9: 在桌面和移动宽度下，导航、列表、表格、Trace 时间线和表单可使用，主要内容不被侧栏遮挡。
- AC10: 自动化测试与静态检查通过，浏览器控制台在主要页面切换和数据加载期间无未处理异常。
