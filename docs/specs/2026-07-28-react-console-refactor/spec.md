# TaleClaw Web 控制台 React 重构 Spec

## 背景

现有 Web 控制台使用单文件原生 HTML、CSS 和 JavaScript，实现了聊天、日志、Runs/Trace、设置预览、文件、分析、记忆和状态页面。功能已经可用，但页面结构、状态管理和交互反馈集中在少量大文件中，页面切换、加载、筛选和主从详情体验偏静态，继续扩展时容易增加耦合。

本次将控制台重构为 React + TypeScript 前端，并使用现代构建工具管理开发与生产资源。现有 Python Web Server、登录 Cookie、API 契约、权限规则和 Runtime 工件保持为系统真源。

## 目标

- 将控制台拆分为边界清晰、可复用和可测试的 React 组件。
- 用统一的状态与数据请求方式管理页面切换、加载、错误、筛选和缓存。
- 改善页面的空间层级、主从布局、即时反馈和连续性，减少“僵硬”的静态页面感。
- 使用克制动效：页面淡入、面板平滑展开、列表选择过渡、骨架加载和操作反馈。
- 保持现有八个主视图、权限、安全边界和后端行为不回退。
- 建立可重复的开发、构建、测试和 Python 服务集成流程。

## 功能需求

- F1: 应用以 React 单页应用运行，包含聊天、日志、Runs/Trace、设置、文件、分析、记忆和状态八个主视图。
- F2: 全局外壳提供桌面侧栏、移动抽屉、账号区、会话列表和主内容区；页面切换不刷新浏览器。
- F3: 页面切换、抽屉、详情展开、筛选结果、加载与错误状态具有轻量过渡或骨架反馈，并尊重用户的减少动态效果偏好。
- F4: 聊天页保留会话搜索、新建/删除、消息 Markdown、流式文本、工具活动、停止生成、模式切换和 Coding Workspace 行为。
- F5: 日志页继续读取真实 Run Trace，支持 Run、关键词和级别筛选；筛选变化即时反馈，Payload 可按需展开。
- F6: Runs/Trace 页继续展示真实 Run 列表、指标、请求摘要、步骤、模型/工具事件、Subagent、Run State 和最终结果；列表选择与详情切换保持上下文连续。
- F7: 设置页继续作为不持久化的前端预览，展示 Provider/API、模型路由、上下文、记忆/RAG、反思和 Subagent 分组，并明确提示尚未接入保存。
- F8: 文件页保留浏览、面包屑、预览、上传、新建目录、重命名、删除和下载行为。
- F9: 分析页保留文本提交、回复展示、状态反馈和记录下载行为。
- F10: 记忆页保留记忆文件选择、刷新、内容展示及空态/错误态。
- F11: 状态页保留用户、角色、会话、模式、Runtime 健康、路径、Workspace 和 Run 概览，并对检查中、就绪和异常状态提供明确反馈。
- F12: 日志与 Runs/Trace 入口只对管理员显示；无权限或未知路由回退聊天页，后端继续执行最终权限校验。
- F13: 合法当前视图、侧栏折叠和 Coding Workspace 等现有本地偏好继续恢复；敏感配置与 Run Payload 不进入持久存储。
- F14: 现有 Python Web Server 可直接提供生产构建资源，并对应用内路由或刷新提供正确入口。

## 非功能需求

- N1: 前端使用 React、TypeScript 和 Vite；依赖数量保持克制，不引入与当前需求无关的大型 UI 框架。
- N2: TypeScript 严格模式开启，API 响应、页面状态和核心组件 Props 具有明确类型。
- N3: 不修改现有 API 请求/响应契约；适配逻辑位于前端数据层。
- N4: 动态内容默认以文本渲染；Markdown 继续使用安全渲染与链接协议限制，Trace Payload 不作为 HTML 执行。
- N5: 日志和 Trace 支持未知事件、缺失字段、超长文本、空数据、请求失败和权限失败。
- N6: 页面达到基本可访问性：语义导航、表单标签、可见焦点、键盘操作、状态提示和减少动态效果支持。
- N7: 1440×900 桌面端和 390×844 移动端均可使用，主要页面不产生不可控的页面级横向滚动。
- N8: 首次加载显示应用骨架；主视图代码可按页面拆分，避免一次加载全部页面逻辑。
- N9: 生产构建不依赖 CDN，静态资源带内容哈希并由 Python Server 正确返回 MIME 类型。
- N10: 保留现有 Python Web/Trace 测试，并增加 React 组件、数据适配和关键交互测试。

## 不做的事

- 不修改 `.env`，不实现设置保存、密钥读取、配置热加载或 Runtime 重启。
- 不改变聊天、文件、分析、记忆、Runs 或 Trace 的后端接口。
- 不新增日志采集服务、数据库、WebSocket 日志尾随或跨进程事件广播。
- 不修改 Runtime、模型路由、工具策略、记忆策略或 Trace 工件格式。
- 不引入完整设计系统产品、复杂动画引擎、3D 效果或重型图表库。
- 不重构登录/注册业务流程；只保证 React 应用与现有 Cookie 登录兼容。
- 不在本次删除 Python Server 现有兼容 Run HTML 页面。

## 验收标准

- AC1: 生产构建成功，Python Web Server 能加载 React 应用及带哈希的 JS/CSS 资源。
- AC2: 八个主视图均由 React 渲染，页面切换无整页刷新且状态连续。
- AC3: 桌面与移动端能观察到克制的页面、抽屉、列表和展开过渡；启用减少动态效果后动画被关闭或显著缩短。
- AC4: 聊天、会话、流式输出、停止、模式、Markdown、工具活动和 Workspace 关键流程保持可用。
- AC5: 日志筛选与 Runs/Trace 主从详情使用真实 API 数据，未知和缺失数据不会导致组件崩溃。
- AC6: 设置页操作不发送配置请求、不写 `.env`、不持久化敏感内容，并显示未接入提示。
- AC7: 文件、分析、记忆和状态页面的现有主要行为保持可用。
- AC8: 普通用户看不到管理员入口，无权限或无效视图回退聊天页，管理员可正常查看 Runs 与日志。
- AC9: 1440×900 和 390×844 下主要视图无页面级横向溢出，键盘可完成导航、筛选和详情展开。
- AC10: TypeScript 检查、Lint、React 测试、生产构建和现有相关 Python 测试全部通过。
- AC11: 浏览器控制台在初始化、八视图切换、真实 Run 加载和错误态演示期间无未处理异常。
