# 新服务器 `.env` 配置手册 Checklist

> 每一项通过读取文档、执行无副作用检查或对照当前仓库配置来验证。

## 实现完整性

- [ ] 独立手册文件存在，开头说明 Ubuntu、Docker Compose、默认项目路径和适用边界。（验证：打开文档并检查首节）
- [ ] 首次创建与已有 `.env` 升级分别提供复制、备份和 `chmod 600` 步骤。（验证：按两条路径逐段模拟命令）
- [ ] 最小配置模板包含 Provider、模型路由、PostgreSQL、Web 登录、工作区、新上下文架构和默认关闭的可选功能。（验证：逐组对照模板）
- [ ] 所有密钥和密码均为明显占位符，没有真实秘密或可误用的弱生产密码。（验证：搜索 `API_KEY`、`PASSWORD`、`DATABASE_URL` 和高熵字符串）
- [ ] 配置被明确分为“必须修改”“建议保持默认”“按需启用”。（验证：检查各分组标签和说明）
- [ ] TaskState、语义压缩、Artifact 外置和动态 Prompt 预算使用当前配置名与默认值。（验证：与 `config.py` 逐项对比）
- [ ] 文档不建议设置三个已被忽略的旧 Coding 固定压缩参数。（验证：搜索 `CODING_CONTEXT_COMPACTION_TRIGGER_TOKENS`、`CODING_CONTEXT_COMPACTION_TARGET_TOKENS`、`CODING_CONTEXT_RECENT_GROUPS`，期望无匹配）

## 路径与数据库安全

- [ ] 文档明确区分宿主机 `/opt/taleclaw` 和容器 `/app`。（验证：检查工作区与 Artifact 路径说明）
- [ ] 文档明确区分容器内 `postgres:5432` 和宿主机 `127.0.0.1:55432`。（验证：检查数据库章节与示例 DSN）
- [ ] 数据库密码特殊字符的 URL 编码要求有明确提示。（验证：检查数据库安全提示）
- [ ] 已有 PostgreSQL 数据卷场景明确说明只改 `.env` 不会修改现有数据库用户密码。（验证：检查故障排查表）
- [ ] Artifact 数据在当前 Compose 下的持久化情况被准确说明，不声称不存在的挂载。（验证：与 `docker-compose.yml` volumes 对照）

## 无秘密泄露验证

- [ ] 文档明确禁止提交、打印或分享真实 `.env`。（验证：检查安全警告）
- [ ] Compose 静态检查使用 `docker compose config --quiet`，不要求输出完整展开配置。（验证：检查命令块）
- [ ] 容器环境检查只输出非敏感值或“已设置/未设置”状态。（验证：逐条审查 `docker compose exec` 命令）
- [ ] 文档没有使用 `cat .env`、无过滤的 `printenv`、完整 DSN 输出或 API Key 回显命令。（验证：全文搜索相关命令模式）
- [ ] Web 默认关闭匿名访问和注册，并提示 HTTPS 生效后启用 Secure Cookie。（验证：检查模板与应用步骤）

## 应用与故障排查

- [ ] 文档说明普通 env 修改后使用 `--force-recreate` 应用新环境。（验证：检查应用配置章节）
- [ ] 文档区分普通运行时 env 变更与需要 `--build` 的镜像构建参数。（验证：检查重启决策说明）
- [ ] 状态检查包含 Compose 服务状态、有限日志和 PostgreSQL ready 检查。（验证：检查命令块可复制性）
- [ ] 故障表至少覆盖数据库地址、已有数据卷密码、Provider 接口、容器路径和未重建容器五类问题。（验证：统计故障表条目及修复方向）
- [ ] RAG/Qdrant、Telegram、飞书只作为按需扩展入口，不混入最小默认部署。（验证：检查可选功能章节）

## 文档集成

- [ ] `docs/README.md` 包含新手册入口。（验证：打开索引并点击相对链接）
- [ ] 手册链接到完整服务器部署文档，所有相对链接目标存在。（验证：解析 Markdown 链接并检查文件）
- [ ] 模板中的变量名都能在 `.env.example`、`docker-compose.yml`、`config.py` 或对应运行时配置中找到。（验证：提取变量名后使用 `rg` 交叉搜索）
- [ ] Git diff 只包含本任务规格文档、新手册和文档索引，没有真实 `.env` 或运行逻辑修改。（验证：运行 `git status --short` 和目标文件 diff）

## 端到端场景

- [ ] 新服务器首次配置：从 `.env.example` 创建 `.env`，填写最小模板，通过权限、Compose 解析和必要变量检查，再启动服务并看到 Web 与 PostgreSQL 状态正常。（验证：在隔离测试目录或逐命令 dry-run，记录每一步结果）
- [ ] 已有服务器安全更新：先备份 `.env`，修改一个非秘密运行时开关，使用 `--force-recreate` 应用后在容器中观察到新值，且备份权限不宽于 `600`。（验证：在隔离环境模拟或审查完整命令链）
- [ ] 错误数据库地址：将现象与故障表对照，能定位容器内不应使用 `127.0.0.1:55432`，并恢复为 `postgres:5432`。（验证：按故障表进行纸面演练）
