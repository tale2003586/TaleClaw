\sectionTitle{项目经历}{\faCode}
%======================================================================
\begin{itemize}
\item \textbf{TaleClaw Agent Runtime（可控工具、上下文管理与可观测执行平台）} 
\begin{itemize}
\item 面对 AI Agent 在多入口接入后会话、工具和运行记录分散的问题，为了支撑 Web、CLI、Telegram 等入口复用同一套执行能力，独立实现统一 Runtime，覆盖会话管理、模型路由、工具执行、插件扩展、记忆和运行报告，形成约 36K 行核心代码和 300+ 个项目内测试用例。
\item 面对工具调用规则容易堆进 prompt、运行过程难以稳定扩展的问题，将一次执行拆分为上下文构建、模型调用、工具执行、结果写回和收尾报告等阶段，并在关键节点接入工具权限、工作区路径校验和 hook 机制，使工具治理从“模型自觉遵守”转为运行时约束。
\item 面对长任务失败后难以复盘的问题，为每次运行记录 trace、metrics、report 和 workspace diff，将上下文构建、模型调用、工具调用、失败原因、token 与耗时沉淀为结构化证据，支持定位“哪一步失败、为什么失败、上下文是否被压缩”。
\item 面对长对话中旧工具结果被裁剪后模型反复重读的问题，将上下文管理升级为分 section 预算、模型调用前 token guard 和可恢复工具结果摘要；旧结果保留引用，必要时可按 id 精确取回，从而降低长任务中“已读证据丢失”的风险。
\end{itemize}

\item \textbf{Coding Agent（面向真实仓库的理解、修改、验证与长任务上下文管理）} 
\begin{itemize}
    \item 面对真实仓库任务中 Agent 容易重复读文件、误派过宽子任务的问题，基于失败 trace 复盘主因，为每个 coding 请求创建独立 task session，绑定 workspace 并记录 diff，使代码修改过程与普通聊天上下文隔离，最终只同步结果、证据和任务日志。
    \item 面对子 Agent 超限和无效 fan-out 的问题，将主 Agent 定位为规划与汇总者，子 Agent 限定为有边界的定位/提取执行体，并通过失败原因、retry hint、scope 校验和任务收窄规则约束重试，让失败能被消费而不是被反复重演。
    \item 面对长 active turn 中工具结果被压缩后模型遗忘的问题，将 working memory 从“结论摘要”升级为任务状态，记录已完成线索、待办队列、已观察调用、不可重复动作和证据索引；当上下文超预算时，把旧工具链吸收到 coding-context-state，只保留近期原文。
    \item 面对中断或步数耗尽后任务需要从零开始的问题，在自然边界写入 checkpoint，保存已完成线索、待处理线索、失败原因和证据，使后续 run 能从待办继续，并在最终回答中合并已完成结论。
    \item 面对 Agent 改动缺少客观对比的问题，建立 30 个本地 smoke task、coding agent matrix 和 SWE-bench Verified 批量运行脚本，对比上下文预算、working memory、step budget 等开关；同时在 Web 端接入实时活动流，展示 step、工具调用、subagent、token 和文件变更，方便调试和演示。

\end{itemize}

\item \textbf{代码安全 RAG（面向代码审查与修复建议的证据检索系统）} 
\begin{itemize}
    \item 面对 Coding Agent 在安全问题上容易只依赖模型常识的问题，基于约 6GB 安全资料构建本地安全知识库，为代码审查和修复建议提供可追溯的漏洞依据和参考证据。
    \item 面对固定窗口切片会破坏漏洞公告和规则语义的问题，分别为安全公告、Semgrep 规则和 Markdown 文档设计结构化切片方式，并保留 CVE、CWE、severity、package、rule id、language 等元数据，使检索结果能回到明确来源。
    \item 面对 query rewrite 可能改写漂移、错误触发 RAG 的问题，重构检索路由为“先召回、再按证据置信度决策”的流程：高置信度直用，中置信度轻量扩展，低置信度再进行 LLM rewrite 或多查询分解，并对强标识符问题保留原文候选。
    \item 面对 RAG 优化缺少数据依据的问题，建立 250 条用户问题的 matrix / ablation 评测，按问题类型观察 p@1、MRR、latency 等指标；同时将检索决策、命中证据和注入内容写入 trace，用于区分问题来自召回、排序还是路由。
\end{itemize}

\end{itemize}
